## v4-small: lemmatized grounding (encoder-gold-v4-small branch)

Same population as v3-small: the pre-corpus-expand five files, extracted to
`data/corpus_v3_small/*.txt` (1475 unique sentences, `no-hypothesis=372`,
`grounding-fail=107` -- identical to v2/v3-small, confirming an unchanged
sentence population and parse path). The one code difference from v3-small:
`build_encoder_gold_v2.ground_word`'s content-word branch now calls
`usvs.senses_of_surface(word)` instead of `usvs.senses_of(word)` (mainline
fix landed on `claude/m27-m28-cleanup` after v3-small was built) -- an
inflected content word (`took`, `depended`, `boats`, ...) that has no direct
WordNet lemma now falls through to `nltk.wordnet.morphy` and grounds on its
lemma's senses instead of falling back to bare `type:"entity"`.

This run also raised the per-sentence parse-cap dial
(`nsm_ct.corpus.CORPUS_MAX_PARSE_SECONDS`, now env-overridable via
`CORPUS_MAX_PARSE_SECONDS`, unset default unchanged at 10.0) to 60s for the
build, specifically to give the 26 sentences v3-small lost to cap-hit under
CPU contention (`dev/ENCODER_GOLD_V3_SMALL_STATS.md`'s "26 total" list) a
chance to parse within budget on this run's (also contended) 4-core CPU env.

### Builder change
`src/nsm_ct/corpus.py`'s `CORPUS_MAX_PARSE_SECONDS` module constant is now `float(os.environ.get("CORPUS_MAX_PARSE_SECONDS", "10.0"))` (was a bare `10.0` literal) -- an env-var override mirroring the existing `GOLD_OUT_JSONL`/`GOLD_CORPUS_GLOB` pattern in `scripts/build_encoder_gold_v2.py`, used by this run to raise the per-sentence parse budget to 60s without touching any other caller's behavior (unset, the default is byte-identical to before).
