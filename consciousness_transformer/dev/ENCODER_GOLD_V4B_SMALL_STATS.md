## v4b-small: POS-aware lemmatization (encoder-gold-v4b-small branch)

v4-small (branch `encoder-gold-v4-small`, built ~1h before this run) added
WordNet-morphy lemmatization to grounding and lifted sense-grounded nodes
4,306 -> 5,860 (`dev/ENCODER_GOLD_V4_SMALL_STATS.md`) -- a real win, but its
own 5 sample records showed the lemmatizer was **POS-BLIND**: `was` -> morphy
noun `wa` -> `washington.n.02`; `can` tagged AUX -> `can.n.01` (the container
noun, not the modal); `engraved` tagged VERB -> `engraved.s.01` (its own raw
lemma, but an ADJECTIVE synset); `to` tagged ADP -> `tho.n.01` (a raw-surface
hit, see below). Function words being run through a content-word
inflectional analyzer is a category error, and a content word's raw surface
can itself ground under the wrong part of speech.

**The fix** (`src/nsm_ct/ground/usvs.py`, `USVS.senses_of_surface`): a new
`pos_hint` parameter -- the tagger's universal-POS tag (`Tag` enum name,
threaded from each record's own `pos` list, aligned with `tokens`) -- now
gates every lemmatization decision:
- a FUNCTION tag (`_FUNCTION_POS_TAGS`: AUX/DET/ADP/PART/PRON/CCONJ/SCONJ/
  PUNCT/NUM/SYM/INTJ) never reaches `morphy` -- only the raw surface is
  looked up, exactly as before this whole lemmatization feature existed;
- a content tag (NOUN/PROPN/VERB/ADJ/ADV, `_UPOS_TO_WN`) restricts `morphy`
  to the WordNet POS(es) that tag maps to, and POS-priority-reorders
  candidates (`_pos_priority_sort`) so a sense whose own WordNet POS
  matches the tagger's tag ranks first -- CANDIDATES-FIRST holds: nothing
  is ever dropped, only reordered/extended;
- when the raw surface already grounds but under the WRONG POS (the
  `engraved` shape), the POS-matched morphy lemma's senses are merged in
  and ranked first, `lemma` staying the raw surface (the entry point that
  actually grounded);
- with no `pos_hint` (unchanged callers), the legacy noun/verb/adj search
  order still applies, plus one added guard: a morphy lemma shorter than 3
  characters recovered from a not-that-short surface is rejected (the
  `was` -> `wa` shape) -- every longer, legitimate morphy lemma is
  unaffected.

Both callers (`build_encoder_gold_v2.ground_word`/`build_clause_dict`/
`build_tree`/`build_record`'s `token_sense_candidates` loop, and
`hand_gold.ground_W`/`_sense_grounding`/`build_tree`/
`build_token_sense_candidates`) now thread the token's own tagger POS
through as `pos_hint`. Predicate/role `token_index` recovery is untouched
(still the same `_IndexMatcher`/`_Matcher` consume-on-match walk) -- POS
lookup for a predicate word (which was never consumed from the matcher
before, and still isn't) is a separate non-consuming case-insensitive
lookup against `tokens`/`pos`; a role word's POS hint is read off the same
index its `token_index` already resolved to, so identical words in
different roles cannot cross-contaminate each other's hint.

Same population, same 60s parse-cap, same `data/corpus_v3_small` glob as
v4-small (`CORPUS_MAX_PARSE_SECONDS=60`,
`GOLD_CORPUS_GLOB=data/corpus_v3_small/real_*.txt`).

The sense-node count DROPS (5860 -> 5411): every function word that used to
morphy-lemmatize into a spurious sense (`was`->`wa`->`washington.n.02`,
`to`(most tokens)->morphy detours, etc.) now correctly falls to `entity`
instead, which is the whole point of the fix -- fewer, but honest,
`type:"sense"` nodes. The POS-match count nearly doubling (2440 -> 4784) is
the direct measurement of the fix: a sense-grounded node's top candidate now
agrees with the tagger's own part of speech roughly twice as often.

**535 function-word tokens still ground as `type:"sense"`** -- this is
correct, not a residual bug: the fix's contract is "never morphy-lemmatize
a function word", not "never sense-ground one". A raw surface that is
ITSELF a genuine WordNet lemma still grounds (`"a"` -> the letter-name noun
`a.n.01` (228 occurrences, the single largest contributor), `"who"` -> a
pronoun-headed noun synset, `"will"`/`"are"`/`"can"`/`"be"`/`"have"` ->
their noun/verb container senses, `"to"` -> `tho.n.01` via the OMW
Spanish-lemma widening -- see below). Spot-checked: every one of the 535 has
`lemma == the raw surface word` (no morphy detour), confirming the guard
holds; the remaining grounding is the SAME raw-surface behavior the
pre-lemmatization pipeline always had for these words, unrelated to this
fix's scope.

**`to` -> `tho.n.01` is NOT a morphy bug and is unchanged by this fix.**
Investigated directly: `usvs.senses_of("to")` returns `['tho.n.01']` on the
RAW surface, with NO morphy involved -- `to` is one of the OMW Spanish
lemmas unioned onto that (proper-noun) synset's lemma list by the
pre-existing Spanish-lemma-widening feature (`spanish_lemmas`,
`dev/SPANISH_SWAP_FEASIBILITY.md`), not a WordNet English lemma at all.
Since `senses_of_surface`'s function-word branch is "raw surface only, no
morphy" (per the fix spec), this raw hit is correctly left as-is -- fixing
it would mean filtering ALREADY-RAW candidates, out of this task's scope
(POS-blind *lemmatization*), and is noted here for transparency rather than
silently left unexplained.

### Sample 4's `support` -- a tagger-limitation side effect, not a fix regression

Sample 4 below re-tags `support` (in `"... she chiefly depended for
support ;"`) as `VERB` (the parser tagger's own call, not this fix's), so
its sense candidates now rank `support.v.01` first instead of v4-small's
`support.n.01` -- grammatically `support` is a noun there. This is exactly
the tradeoff the task's directive ("content words must be lemmatized with
the tagger's part of speech") accepts: `senses_of_surface` now faithfully
follows the tagger's tag, so a tagger mistake can flip a previously-correct
MFS-ordered noun-first ranking to a verb-first one. Fixing the tagger
itself is out of this task's scope (`usvs.py`'s lemmatization logic, not
`quantum_parser`'s POS tagger).
